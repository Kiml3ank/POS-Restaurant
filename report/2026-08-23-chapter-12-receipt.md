## 2. โครงข้อมูล

### 2.1 `Receipt` แยกจาก `Payment` — และทำไมไม่ยัดคอลัมน์เพิ่ม

`Payment` = **เงินที่ได้รับ** · `Receipt` = **เอกสารที่ออกให้ลูกค้า** แยกแล้วได้สามอย่าง
ที่รวมกันแล้วทำไม่ได้:

1. **snapshot ตัวตนผู้ขาย ณ วันที่ออกใบ** (`sellerName` `sellerTaxId` `sellerBranchName`
   `sellerAddress` `sellerPhone`) — ร้านเปลี่ยนชื่อ ย้ายที่อยู่ หรือเพิ่งได้เลขผู้เสียภาษี
   มาทีหลังได้ แต่ใบที่พิมพ์ซ้ำปีหน้า **ต้องเหมือนใบที่ลูกค้าถืออยู่**
   (กฎเดียวกับที่ห้ามอ่านอัตรา VAT จาก `Branch` ตอนพิมพ์ใบเก่า) — มีเทสต์ตรึงไว้
2. **นับ/สืบการพิมพ์ซ้ำ** (`printCount` `firstPrintedAt` `lastPrintedAt`) ไม่ใช่ข้อมูลการเงิน
3. **ใบลดหนี้ตอนทำ Refund ในอนาคต** จะเป็น `Receipt` **อีกแถวที่อ้างถึงใบเดิม**
   ไม่ใช่การแก้ใบเก่า — โครงนี้รองรับตั้งแต่ต้นโดยไม่ต้อง migrate ซ้ำ

### 2.2 `DocumentCounter` — ตัวเดินเลขต่อ (สาขา, ชุดเอกสาร)

```ts
const counter = await tx.documentCounter.update({
  where: { branchId_series: { branchId, series: "ABB" } },
  data:  { lastSeq: { increment: 1 } },
  select: { lastSeq: true },
});
```

| สมบัติ | ได้มายังไง | เทสต์ที่พิสูจน์ |
|---|---|---|
| เลขไม่ซ้ำแม้กดพร้อมกัน | row lock ของ Postgres บนแถวเดียว | `Promise.all` สองการรับเงิน → ได้ 10 กับ 11 counter ขยับ 2 พอดี |
| **เลขไม่ขาดเป็นรู** | อยู่ใน transaction เดียวกับการรับเงิน rollback แล้วคืนเลข | ยิง `issueReceipt` ด้วย `paymentId` ซ้ำ → ชน unique → counter กลับไปที่เดิม |
| ไม่มีบิลที่จ่ายแล้วแต่ไม่มีเอกสาร | commit พร้อมกันหรือไม่เกิดเลย | ทุกเคสรับเงินเช็ค `receipt` ต่อท้าย |

**ราคาที่จ่าย:** การรับเงินของสาขาเดียวกันเข้าคิวกันที่แถว counter แถวเดียว —
เป็น **ต้นทุนที่หลีกเลี่ยงไม่ได้ของคำว่า "เลขต่อเนื่อง"** ไม่ใช่ข้อบกพร่องของ design

**ออกใบอัตโนมัติตอนรับเงิน ไม่ใช่ตอนกดพิมพ์** — ถ้าให้ "กดพิมพ์ = ออกเลข"
แคชเชียร์เลี่ยงการออกใบได้ และเลขจะขาด ซึ่งเป็นสิ่งเดียวที่ตรวจสอบไม่ผ่านแน่ ๆ

### 2.3 `number` เป็น unique **ต่อสาขา** ไม่ใช่ทั้งระบบ

จับได้ตอนกำลังจะเขียน backfill: `Branch.code` ไม่ซ้ำแค่ภายใน tenant เดียวกัน
(`@@unique([tenantId, code])`) สอง tenant จึงมีสาขาชื่อ `HQ` ได้ทั้งคู่ แล้ว
`HQ-00000001` จะชนกันข้ามร้านที่ไม่เกี่ยวอะไรกันเลย → `@@unique([branchId, number])`

### 2.4 `kind` ถูก snapshot ตอนออกใบ ไม่ derive ตอน render

`currency === "THB"` → `TAX_ABB` (มีคำว่าใบกำกับภาษี + เลขผู้เสียภาษี) · อื่น ๆ → `RECEIPT`

**เลขผู้เสียภาษีถูกตัดตั้งแต่ตอนเขียนลงฐาน** (`sellerTaxId: kind === "TAX_ABB" ? … : null`)
ไม่ใช่ตัดตอนแสดงผล — เพื่อให้ไม่มีทางหลุดออกไปแม้จะมีใครเขียนหน้าจอใหม่แล้วลืมเงื่อนไข
(หน้าจอมีเงื่อนไขซ้ำอีกชั้นเป็นชั้นที่สอง ไม่ใช่ชั้นเดียว)

### 2.5 Migration เขียน backfill เอง

`--create-only` แล้วต่อ SQL ท้ายไฟล์: สร้างแถว counter ให้ทุกสาขา → ออกใบย้อนหลังให้
`Payment` ที่มีอยู่เรียงตาม `paidAt` ต่อสาขา (`row_number() OVER (PARTITION BY …)`)
→ ดัน `lastSeq` ให้ตรง · **ห้ามปล่อยให้มี Payment ที่ไม่มีใบเสร็จ** ไม่งั้น
`/admin/receipts` จะแสดงน้อยกว่าการรับเงินจริงตั้งแต่วันแรก แล้วคนกระทบยอดจะสรุปว่าเอกสารหาย

### 3.1 ทำไม `issueReceipt` ต้องอยู่คนละไฟล์กับ `getReceipt`

`receipt.ts` (อ่าน) ต้องใช้ `getPayment()` จาก `payment.ts` · `payment.ts` ต้องเรียก
`issueReceipt()` — รวมไฟล์เดียวจะได้ **import cycle** ทันที ESM รันผ่านก็จริงเพราะ
ทุกการเรียกอยู่ในฟังก์ชัน แต่เป็นกับดักที่รอวันมีคนเพิ่ม const ระดับบนสุดแล้วพังตอน
runtime โดยที่ tsc ไม่ฟ้อง → `receipt-issue.ts` เป็น **leaf** โดยตั้งใจ
**ห้ามเพิ่ม import ที่ชี้กลับไปหา `payment.ts` หรือ `receipt.ts` ในไฟล์นั้นเด็ดขาด**

### 3.2 สองเส้นทางบาง ๆ บนคอมโพเนนต์ตัวเดียว — ไม่สร้าง auth แบบที่สี่

```
app/(pos)/pos/receipt/[receiptId]/page.tsx        ← cookie pos    (ด่าน session เท่านั้น)
app/(admin)/admin/receipts/[receiptId]/page.tsx   ← cookie admin  (ด่าน session เท่านั้น)
        ↓ ทั้งคู่ render ตัวเดียวกัน

```

**ไม่ทำ `/receipt/[id]` ที่รับ cookie ใบไหนก็ได้** เพราะเป็นการเพิ่มรูปแบบ auth
แบบที่สี่เข้ามาในระบบที่มีกติกาเดียวชัด ๆ ว่า *"หนึ่งจอ = หนึ่ง cookie = หนึ่งกฎใน `proxy.ts`"*
→ **`proxy.ts` ไม่ต้องแก้เลยทั้งบท** · Server Action ก็มีคู่แฝดสองตัวด้วยเหตุผลเดียวกัน
(`posPrintReceiptAction` / `adminPrintReceiptAction`) — ตรรกะจริงอยู่ที่
`recordReceiptPrint()` ที่เดียว สองตัวนั้นเป็นแค่ด่าน session

## 4. กับดักที่เจอจริงในบทนี้

### 4.1 ⚠ `h-dvh overflow-hidden` ตัดใบเสร็จครึ่งใบตอนพิมพ์

เชลล์ของทั้ง `(pos)` `(kds)` `(admin)` เป็น `h-dvh overflow-hidden` เพื่อให้แต่ละแพเนล
เลื่อนแยกกัน — สั่งพิมพ์ทั้งที่กฎนั้นยังอยู่จะได้ **กระดาษหน้าเดียวเท่าความสูงจอ
แล้วตัดที่เหลือทิ้งเงียบ ๆ** โดยที่ tsc/build ไม่ฟ้องอะไร

วัดจริงด้วย CDP `Emulation.setEmulatedMedia` ที่จอสูง 400px:

| | เชลล์ | `documentElement.scrollHeight` | ความสูงใบ |
|---|---|---|---|
| จอปกติ | `overflow: hidden`, 400px | 400 | 790 ← **ถูกตัด** |
| โหมดพิมพ์ | `overflow: visible`, 913px | 913 | 765 ← ครบ |

`@media print` ใน `globals.css` จึงต้องทำสามอย่างเสมอ: ปลดเชลล์ · ซ่อน
`[data-print-hide]` · ตั้ง `@page { size: 80mm auto; margin: 0 }`
**ทุกครั้งที่เพิ่มหน้าที่พิมพ์ได้ ต้องทดสอบด้วยการ emulate print media จริง ไม่ใช่ดูด้วยตา**

### 4.2 ⚠ Git Bash แปลง path ที่ขึ้นต้นด้วย `/` ในอาร์กิวเมนต์

`node script.mjs /admin/menu` → สคริปต์ได้ `C:/Program Files/Git/admin/menu`
(MSYS path conversion) แล้ว `BASE + path` กลายเป็น URL ที่ navigate ไม่ได้
**เบราว์เซอร์ค้างที่ `about:blank` แล้วสคริปต์รายงานว่า "ผ่าน" ทุกเคส**

เสียเวลาไปพอสมควรกับเรื่องนี้ (screenshot ออกมาดำทั้งภาพก็สาเหตุเดียวกัน)
สองอย่างที่ต้องทำตั้งแต่ต้นทุกครั้ง:

1. ตั้ง **`MSYS_NO_PATHCONV=1`** เวลาส่ง path เป็นอาร์กิวเมนต์ (หรือห่อใน JSON string)
2. **สคริปต์ตรวจ UI ต้องยืนยัน `location.href` ว่าตรงกับที่สั่งไป** ก่อนเชื่อผลวัด
   — `audit.mjs` มีด่าน `INVALID` แล้ว การวัดที่ไม่ได้อยู่บนหน้าที่ตั้งใจต้องนับเป็น
   "วัดไม่ได้" ไม่ใช่ "ผ่าน"

### 4.3 ⚠ `Receipt → Payment` เป็น Restrict — ทุก resetTable พังพร้อมกัน

สายการลบยาวขึ้นอีกหนึ่งชั้น: **ออร์เดอร์ → ใบเสร็จ → การรับเงิน → รอบโต๊ะ**
แก้ไปแล้วทั้ง `dev:reset-table` และ smoke ทั้งห้าชุดเดิม (สี่ชุดต้องเพิ่มตัวแปร
`paymentIds` ที่ยังไม่มี) — **บทถัดไปที่เพิ่มตารางผูกกับ `Payment` ต้องไล่จุดเดิมนี้อีก**

### 4.4 ⚠ แถบหัวจอกับแถบโมดูลติดไปบนกระดาษ — และเทสต์ที่ปล่อยให้ผ่าน

**ผู้ใช้เจอจากการกดพิมพ์จริง** หลังจากเทสต์อัตโนมัติบอกว่าผ่านหมด

สาเหตุ: `data-print-hide` ถูกแปะแค่ในหน้าใบเสร็จ แต่ `<header>` ของ `(pos)`/`(admin)`
กับ `<nav>` ของ `pos-sidebar` / `admin-nav` **อยู่ที่ layout ของ route group**
ซึ่งอยู่นอกหน้าที่เขียนไป จึงไม่ถูกซ่อน

**บทเรียนที่สำคัญกว่าตัวบั๊ก:** เทสต์เดิมถามผิดคำถาม —
ถามว่า *"ของที่แปะป้ายไว้ถูกซ่อนไหม"* ซึ่งตอบว่า "ใช่" ได้เสมอแม้จะลืมแปะที่ไหน
คำถามที่ถูกคือ *"มีอะไรอื่นเหลืออยู่บนกระดาษไหม"* — ตอนนี้เทสต์เดินทุก element
ที่ไม่ได้อยู่ในตัวใบแล้วยืนยันว่าไม่มีตัวไหนกินพื้นที่ (`strays.length === 0`)
พร้อมด่านคู่กันว่า **บนจอปกติต้องยังเห็นแถบครบ** (กันซ่อนผิดที่)

รันผลก่อนแก้ vs หลังแก้:

```
ก่อน  โหมดพิมพ์ strays: ["HEADER.flex h-[58px]…", "A.flex…", "SPAN…"]   ← ติดไปด้วย
หลัง  โหมดพิมพ์ strays: []                                              ← สะอาด
      จอปกติ   strays: [HEADER, …]                                      ← ยังอยู่ครบ
```

**กฎที่ต้องจำ:** หน้าใหม่ที่พิมพ์ได้ ต้องแปะ `data-print-hide` ที่ **ตัวครอบของ chrome
ทุกชั้น รวมถึงที่อยู่ใน layout ของ route group** ไม่ใช่แค่ในไฟล์หน้านั้น

### 4.5 หมายเหตุเรื่องขนาดกระดาษ

`@page { size: 80mm auto }` ถูกใช้จริงเมื่อปลายทางรองรับ — **"Save as PDF"
และไดรเวอร์เครื่องพิมพ์ความร้อนใช้ตามนี้** ส่วนปลายทางที่มีขนาดกระดาษตายตัว
(เช่น "Microsoft Print to PDF" ที่ตั้งเป็น A4/Letter) เบราว์เซอร์จะใช้ขนาดของ
ปลายทางแทน แล้วใบจะไปวางชิดมุมบนซ้ายของกระดาษใหญ่ ซึ่งถูกต้องตามที่ตั้งใจ
(`margin: 0` ทั้ง `@page` และตัวใบ) ไม่ใช่บั๊ก

## 6. ยังไม่ได้ทำในบทนี้ (ตั้งใจ)

- **ใบกำกับภาษีเต็มรูป** — ตกลงตัดออกจากขอบเขต · โครง `series` ใน `Receipt`/`DocumentCounter`
  รองรับไว้แล้ว เพิ่มชุดใหม่ได้โดยไม่ต้อง migrate โครง
- **e-Tax Invoice / XML** — ต้องขึ้นทะเบียนกับกรมสรรพากรก่อน ไม่ใช่งานที่จบในโค้ด
- **ส่งใบเสร็จให้ลูกค้าทางมือถือ** — ตอนนี้ใบเปิดได้เฉพาะพนักงาน (cookie ของจอ)
  ถ้าจะให้ลูกค้าเปิดเองต้องมี token แบบอ่านอย่างเดียวต่อใบ = งานของตัวเอง
- **ส่วนลด** — สูตรกับคอลัมน์พร้อมแล้ว ใบเสร็จแสดงบรรทัดส่วนลดได้แล้วถ้ามีค่า
  แต่ **ยังไม่มีปุ่ม** เพราะต้องมาพร้อมจำกัดสิทธิ์ + บังคับเหตุผล + AuditLog (บทที่ 13)
- **Refund / ใบลดหนี้** — ต้องเป็นเอกสารใบใหม่ที่อ้างใบเดิม ห้ามย้อนสถานะบิลเดิม
