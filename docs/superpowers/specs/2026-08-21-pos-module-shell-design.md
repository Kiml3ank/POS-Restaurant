# Spec — ปรับ POS เป็นระบบโมดูลตาม design "Cafe POS" (ก้อน A)

**วันที่:** 2026-08-21
**ที่มา:** Claude Design project `Cafe POS system UI` (`3b23f6c7-3d12-4af1-802f-5681dc54f15b`)
**ขอบเขต:** เฉพาะ route group `(pos)` + `lib/server/cart.ts` — ไม่แตะหน้าลูกค้า KDS หลังร้าน
**ก้อนถัดไปหลังจากนี้:** ก้อน B = KDS (บทที่ 8) ซึ่ง spec นี้เตรียมที่ทางไว้ให้แล้ว

## 1. ปัญหาที่จะแก้

ทุกวันนี้จอพนักงานบังคับให้เดินทางเดียว: ล็อกอิน → ผังโต๊ะ → กดโต๊ะ → ถึงจะเจอเมนูกับตะกร้า
ผลคือคนที่เปิดมาครั้งแรกไม่เจอตะกร้าและไม่รู้ว่าต้องกดอะไรก่อน (ผู้ใช้รายงานเข้ามาจริง 2 ครั้ง)

design วางระบบไว้คนละแบบ: เป็นแอปหน้าจอเดียวที่ **sidebar สลับโมดูล** และ **จอแคชเชียร์
เป็นจอแรก** โดยเลือกโต๊ะ/สั่งกลับบ้านจาก chips ที่อยู่ในแผงตะกร้าเลย ไม่ต้องเปลี่ยนหน้า

spec นี้ย้ายโครง `(pos)` มาเป็นแบบนั้น และเพิ่มความสามารถ "สั่งกลับบ้าน" ที่ schema
รองรับอยู่แล้วแต่โค้ดยังใช้ไม่ได้

## 2. สิ่งที่ไม่อยู่ในขอบเขต

- KDS (ก้อน B)
- คิดเงิน/รับชำระ, ส่วนลด, ภาษี (บทที่ 10-11) — แผงตะกร้ายังโชว์แค่ `subtotal`
- ย้าย/รวมโต๊ะ, แยกบิล (ส่วนที่เหลือของบทที่ 9)
- โมดูล Products / Inventory / Reports / Users (บทที่ 13-15) — เป็นรายการจางใน sidebar
- หน้าลูกค้า `(customer)` — เปลี่ยนแค่ call site ที่จำเป็นเพราะ signature ของ cart เปลี่ยน
  **ผลลัพธ์ที่ผู้ใช้เห็นต้องเหมือนเดิมทุกพิกเซล**

## 3. โครงเส้นทางใหม่

| เส้นทาง | โมดูล | หมายเหตุ |
|---|---|---|
| `/pos` | **แคชเชียร์** | จอหลัก · `?table=<id>` \| `?svc=takeaway` \| `?view=bills` \| `?cat=<id>` |
| `/pos/tables` | **โต๊ะและออร์เดอร์** | ผังโต๊ะ (ย้ายมาจาก `/pos` เดิม) |

| `/pos/login` | — | เหมือนเดิม |
| `/pos/table/[tableId]` | — | **redirect ถาวรไป `/pos?table=<tableId>`** |

| `/pos/table/[tableId]/menu/[itemId]` | — | ลบทิ้ง (ย้ายไป `/pos/menu/[itemId]`) |

### พารามิเตอร์ของจอแคชเชียร์

| param | ค่า | ความหมาย |
|---|---|---|
| `table` | `<tableId>` | ทานที่ร้าน ผูกกับโต๊ะนี้ |
| `svc` | `takeaway` | สั่งกลับบ้าน ไม่ผูกโต๊ะ |
| *(ไม่มีทั้งคู่)* | — | ยังไม่เลือก — เมนูแสดงปกติ แผงขวาให้เลือกก่อน |
| `view` | `bills` | แพเนลซ้ายสลับไปดูบิลที่ส่งเข้าครัวแล้ว (เฉพาะโหมดโต๊ะ) |
| `cat` | `<categoryId>` | หมวดเมนูที่เปิดอยู่ |

`table` กับ `svc` ต้องไม่มาพร้อมกัน — ถ้ามาพร้อมกันให้ `table` ชนะและ `svc` ถูกละทิ้ง

**ทำไมเก็บใน URL ไม่ใช่ client state:** ทุกหน้าใน `(pos)` เป็น Server Component
และกดได้ก่อน JS โหลดเสร็จ (กติกาที่ตั้งไว้ตั้งแต่บทที่ 7) — และแคชเชียร์กดปุ่ม
back ของเบราว์เซอร์เป็นประจำ สถานะจึงต้องอยู่ในประวัติการเดินทาง

## 4. ตะกร้าที่ไม่ผูกโต๊ะ — `CartOwner`

### 4.1 ปัญหา

`lib/server/cart.ts` ทุกฟังก์ชันรับ `tableSessionId: string` เป็นกุญแจของตะกร้า
ออร์เดอร์กลับบ้านไม่มีรอบโต๊ะ จึงไม่มีกุญแจให้ใช้

### 4.2 ทางแก้

เปลี่ยนกุญแจเป็น discriminated union ที่บอกชัดว่าตะกร้าใบนี้เป็นของใคร:

```ts
export type CartOwner =
  | { kind: "table"; tableSessionId: string }
  | { kind: "takeaway"; staffId: string };
```

พร้อม helper ตัวเดียวที่แปลงเป็น `where` — **ทุกฟังก์ชันต้องใช้ helper นี้ ห้ามเขียน
เงื่อนไขเองซ้ำ** เพราะถ้าที่ไหนลืมเงื่อนไขข้อใดข้อหนึ่ง ตะกร้าจะรั่วข้ามคน:

```ts
function cartWhere(owner: CartOwner): Prisma.OrderWhereInput {
  return owner.kind === "table"
    ? { status: "DRAFT", tableSessionId: owner.tableSessionId }
    : {
        status: "DRAFT",
        tableSessionId: null,
        type: "TAKEAWAY",
        placedByStaffId: owner.staffId,
      };
}
```

### 4.3 ทำไมตะกร้ากลับบ้านผูกกับ "พนักงาน" ไม่ใช่ "เครื่อง"

ทางเลือกที่พิจารณา:

1. **ผูกกับพนักงานที่ล็อกอินอยู่** ← เลือกอันนี้
   ไม่ต้องเพิ่มตารางหรือคอลัมน์ใหม่เลย ใช้ `placedByStaffId` ที่มีอยู่ และตรงกับ
   ความจริงหน้าร้าน: คนที่กดรับออร์เดอร์คือคนที่รับผิดชอบบิลนั้น ถ้าเขาล็อกจอแล้ว
   คนใหม่มากด จะเป็นตะกร้าคนละใบ ซึ่งถูกต้อง
2. ผูกกับเครื่อง (terminal id ใน cookie) — ต้องออกและเก็บ id ของเครื่องเพิ่ม
   และผิดเวลาสองคนสลับกันกดเครื่องเดียวกันกลางออร์เดอร์
3. เพิ่มตาราง `TakeawayCart` — เกินจำเป็น ตะกร้าคือ `Order` อยู่แล้ว

**ผลข้างเคียงที่ต้องยอมรับ:** ถ้าแคชเชียร์ล็อกจอทิ้งไว้ตอนที่ยังมีตะกร้ากลับบ้านค้าง
ตะกร้าใบนั้นจะค้างใน DB จนกว่าจะมีคนล็อกอินด้วยรหัสเดิมแล้วมาเจอ — ยอมรับได้ในก้อนนี้
เพราะเลขบิลถูกออกไปแล้วและการลบทิ้งอัตโนมัติเสี่ยงลบของที่ยังใช้อยู่
(การเก็บกวาดบิล DRAFT ค้างเป็นงานของบทที่ 15 ตอนปิดวัน)

### 4.4 signature ที่เปลี่ยน

| เดิม | ใหม่ |
|---|---|
| `getCart(tableSessionId: string)` | `getCart(owner: CartOwner)` |
| `setCartLineQuantity(tableSessionId, orderItemId, quantity)` | `setCartLineQuantity(owner, orderItemId, quantity)` |
| `placeOrder(tableSessionId, options)` | `placeOrder(owner, options)` |
| `AddToCartInput.tableSessionId: string` + `tableId: string` | `AddToCartInput.owner: CartOwner` + `tableId: string \| null` |
| `getPlacedOrders(tableSessionId: string)` | **ไม่เปลี่ยน** — ใช้เฉพาะหน้าติดตามออร์เดอร์ของลูกค้าที่มีโต๊ะเสมอ |

`getOrCreateDraftOrder` สร้างบิลใหม่ด้วยค่าต่างกันตาม owner:

| ฟิลด์ | `kind: "table"` | `kind: "takeaway"` |
|---|---|---|
| `tableSessionId` | จาก owner | `null` |
| `tableId` | จาก input | `null` |
| `type` | `DINE_IN` | `TAKEAWAY` |
| `placedByStaffId` | `null` (ตั้งตอน place) | `owner.staffId` **ตั้งตั้งแต่สร้าง** |
| `channel` | จาก input | `POS` |

> `placedByStaffId` ของตะกร้ากลับบ้านถูกตั้งตั้งแต่ตอนสร้าง ไม่ใช่ตอนกดส่ง
> เพราะมันทำหน้าที่เป็น **กุญแจของตะกร้า** ด้วย ต้องเขียนคอมเมนต์กำกับไว้ในโค้ด
> ไม่งั้นคนอ่านทีหลังจะงงว่าทำไมบิลที่ยังไม่ส่งถึงมีคนกดส่งแล้ว

### 4.5 call site ที่ต้องแก้

- `app/(customer)/t/[tableCode]/actions.ts` — ห่อเป็น `{ kind: "table", tableSessionId: … }`
- `app/(pos)/pos/actions.ts` — สร้าง owner จาก formData (ดูหัวข้อ 6)
- `lib/server/pos.ts` — ไม่ต้องแก้ (เรียกแค่ `recalculateOrderSubtotal`)
- `scripts/smoke-customer-order.ts`, `scripts/smoke-pos-staff.ts` — ห่อค่าเดิม

## 5. หน้าจอ

### 5.1 `/pos` — แคชเชียร์

```
┌ 58px ────────────────────────────────────────────┬──────────────────┐
│ [เมนู][บิลที่ส่งแล้ว n][หมวด…]          n เมนู    │  แผงตะกร้า 412px │
├──────────────────────────────────────────────────┤                  │
│                                                  │                  │
│           ตารางเมนู (ink-grid, ไทล์ 134px)        │                  │
│                                                  │                  │
└──────────────────────────────────────────────────┴──────────────────┘
```

- แถบบนสุด (66px) กับ sidebar (268px) มาจาก layout อยู่แล้ว
- แท็บ "บิลที่ส่งแล้ว" แสดงเฉพาะโหมดโต๊ะ (กลับบ้านไม่มีบิลเก่าให้ดู)
- **เมนูฝั่งซ้ายแสดงเสมอ** แม้ยังไม่เลือกโต๊ะ — เป็นจุดที่แก้ปัญหาเดิมโดยตรง
  แต่ไทล์เมนูจะกดไม่ได้ (ลิงก์กลายเป็น `<span>` จาง) พร้อมข้อความชี้ไปที่แผงขวา

### 5.2 แผงตะกร้าขวา

เรียงตาม design จากบนลงล่าง:

1. **หัวแผง** — `orderTitle` = ชื่อโต๊ะ / "กลับบ้าน" / "ยังไม่เลือก"
   `orderSub` = เลขบิลเมื่อมีตะกร้าแล้ว · ถ้ายังไม่มีตะกร้าให้ขึ้น "ยังไม่มีบิล"
   (เลขบิลออกตอนหยิบของชิ้นแรกใส่ตะกร้า ไม่ใช่ตอนเลือกโต๊ะ — ตรรกะเดิมของ `getOrCreateDraftOrder`)
2. **`serviceOpts`** — segmented 2 ช่อง `[ทานที่ร้าน][กลับบ้าน]` เป็นลิงก์ไป `?table=`/`?svc=takeaway`
   - กด "ทานที่ร้าน" ตอนที่ยังไม่มีโต๊ะ = ล้าง `svc` แล้วรอเลือกโต๊ะ
3. **`tableOpts`** — chips ของโต๊ะทั้งสาขา (เฉพาะโหมดทานที่ร้าน) จาก `getPosTables()`
   - โต๊ะที่เปิดอยู่: ป้ายปกติ · โต๊ะว่าง: จางลง · โต๊ะที่เลือก: พื้น accent
   - **แถว chips ต้อง wrap ได้** (`.ink-row` + `flex-wrap`) เพราะสาขาจริงมีโต๊ะหลายสิบใบ
     ส่วน design ต้นทางมีแค่ 6 ใบพอดีแถวเดียว — ห้ามยึดตามนั้นแล้วปล่อยให้ล้น
4. **กล่องเปิดโต๊ะ** — แสดงเมื่อโต๊ะที่เลือกยังไม่มีรอบเปิด: เลือกจำนวนคน + ปุ่ม "เปิดโต๊ะ"
   (ใช้ `OpenTableForm` เดิม เปลี่ยนแค่ปลายทาง redirect)
5. **รายการในตะกร้า** — เหมือนที่ทำไว้แล้ว (stepper + หมายเหตุ + ตัวเลือก)
6. **สรุปยอด** — `ค่าอาหาร` / หมายเหตุว่า VAT อยู่บทที่ 10 / `รวม` ตัว 34px
7. **ปุ่ม** — `[ส่งเข้าครัว]` เต็มความกว้าง

สถานะพิเศษของแผง:

| สถานการณ์ | แผงขวาแสดง |
|---|---|
| ยังไม่เลือกอะไร | serviceOpts + chips + ข้อความ "เลือกโต๊ะหรือกดกลับบ้านเพื่อเริ่ม" |
| เลือกโต๊ะที่ยังไม่เปิด | serviceOpts + chips + กล่องเปิดโต๊ะ |
| โต๊ะเปิดแล้ว / กลับบ้าน | serviceOpts + chips + รายการ + ยอด + ปุ่มส่ง |

## 6. Server Action ที่เปลี่ยน

`app/(pos)/pos/actions.ts` — ทุก action ที่แตะตะกร้าต้องประกอบ `CartOwner` เอง
จาก formData แล้วตรวจสิทธิ์ก่อนเสมอ:

```
resolveCartOwner(staff, formData) →
  formData.svc === "takeaway"  → { kind: "takeaway", staffId: staff.id }
  formData.tableId มีค่า        → หา session ที่เปิดอยู่ของโต๊ะนั้นในสาขาของ staff
                                 → { kind: "table", tableSessionId }
                                 → ไม่พบ = error "โต๊ะนี้ยังไม่ได้เปิด"
  ไม่มีทั้งคู่                    → error "กรุณาเลือกโต๊ะหรือเลือกสั่งกลับบ้าน"
```

| action | เปลี่ยนอะไร |
|---|---|
| `posAddToCartAction` | ใช้ `resolveCartOwner` · redirect กลับ `/pos?<ctx>&cat=<catId>` |
| `posSetLineQuantityAction` | ใช้ `resolveCartOwner` |
| `posPlaceOrderAction` | ใช้ `resolveCartOwner` · หลังส่งสำเร็จ redirect ไป `/pos?<ctx>` |
| `openTableAction` | redirect ไป `/pos?table=<id>` แทน `/pos/table/<id>` |
| `closeTableAction` | redirect ไป `/pos/tables` |
| `cancelItemAction` | ไม่เปลี่ยน (ทำงานที่ระดับ `orderItemId` อยู่แล้ว) |

**ห้ามเชื่อ `tableId` ที่มากับฟอร์ม** — ต้อง resolve เป็น session ผ่าน `staff.branchId`
ทุกครั้ง เพราะ Server Action ถูกยิงตรงด้วย POST ได้ (กติกาเดิมของโปรเจกต์)

## 7. การจัดการข้อผิดพลาด

| กรณี | พฤติกรรม |
|---|---|
| `?table=` ชี้ไปโต๊ะที่ไม่มีในสาขา | จอแคชเชียร์ทำเหมือน "ยังไม่เลือกโต๊ะ" ไม่ใช่ 404 (แคชเชียร์กด back เจอ URL เก่าได้) |
| กดส่งเข้าครัวตอนตะกร้าว่าง | ปุ่ม disabled อยู่แล้ว + `placeOrder` คืน error เดิม |
| กดส่งซ้ำ | ตรรกะเดิมของ `placeOrder` ไม่เปลี่ยน — คืนสำเร็จ ไม่สร้างบิลใหม่ |
| รอบโต๊ะหมดอายุระหว่างกด | `resolveCartOwner` หา session ไม่เจอ → error ชวนให้เปิดโต๊ะใหม่ |
| เลือกกลับบ้านแล้วสลับเป็นโต๊ะทั้งที่ตะกร้ากลับบ้านมีของ | **ตะกร้าทั้งสองใบอยู่แยกกัน ไม่ย้ายของข้ามกัน** สลับกลับมาแล้วของยังอยู่ครบ |

## 8. การทดสอบ

### 8.1 `npm run smoke:pos` — เพิ่มจาก 58 เคส

เคสใหม่ที่ต้องมี:

1. ตะกร้ากลับบ้านของพนักงาน A กับ B **แยกกันคนละใบ**
2. ตะกร้ากลับบ้านกับตะกร้าโต๊ะของพนักงานคนเดียวกัน **ไม่ปนกัน**
3. ส่งตะกร้ากลับบ้านเข้าครัว → `type = TAKEAWAY`, `tableSessionId = null`, `tableId = null`
4. `setCartLineQuantity` ด้วย owner ผิดคน → error (ยิง id ข้ามตะกร้าไม่ได้)
5. `getCart` ของ owner กลับบ้านต้องไม่คืนบิลของโต๊ะ และกลับกัน
6. เคสเดิมทั้ง 58 ยังผ่านเท่าเดิม (ตรรกะไม่ได้เปลี่ยน แค่เปลี่ยนวิธีระบุตะกร้า)
