## 1. จุดตัด (breakpoint) ที่เลือก และเหตุผล

| ของ | จอแคบ | จุดตัด | จอกว้าง |
|---|---|---|---|
| แถบโมดูลของ POS | แถบล่าง | `lg` (1024) | แถบซ้าย 268px |
| ตะกร้าของหน้าโต๊ะ | แถบสรุปล่าง กางได้ | `xl` (1280) | แผงปักขวา 412px |
| กริดโต๊ะ / กริดเมนู | 1 คอลัมน์ | `sm`/`lg`/`xl` | สูงสุด 4 / 3 คอลัมน์ |
| สองคอลัมน์ของหน้าล็อกจอ | ซ้อนกัน | `xl` (1280) | `1fr` + 620px |

**ทำไมตะกร้าตัดที่ `xl` ไม่ใช่ `lg`:** ที่ 1024px ถ้ายังปักตะกร้าไว้ขวา
จะเหลือให้เมนู 1024 − 268 (แถบซ้าย) − 412 (ตะกร้า) = **344px** ซึ่งวางเมนูสองคอลัมน์
ไม่ได้เลย ที่ `xl` เหลือ 600px ซึ่งพอ

**ทำไมหน้าล็อกจอตัดที่ `xl` ไม่ใช่ `lg`:** เจอจากการวัดจริง — ที่ 1024px พอดี
คอลัมน์ขวากิน 620px คงที่ เหลือซ้าย 404px แล้วหัก padding 128px เหลือ 276px
แต่ wordmark "KITCHEN" ที่ 76px กว้างกว่านั้น → **ล้นออกนอกจอ 78px**
(หน้า POS ไม่โผล่อาการเพราะคำว่า "POINT OF" สั้นกว่า — เคสนี้จับได้ด้วยการวัด
ทุกหน้าทุกความกว้าง ไม่ใช่ด้วยการเปิดดูหน้าที่นึกออก)

## 2. สิ่งที่เปลี่ยนไปในแต่ละจอ

### เครื่องพนักงาน (POS)

- **`pos-sidebar.tsx`** — บนจอกว้างยังเป็นแถบซ้ายเต็มรูป (แผนที่ของระบบ
  พร้อมโมดูลที่ยังไม่ได้ทำ + เลขบท) บนจอแคบเปลี่ยนเป็น **แถบล่าง** ที่แสดง
  **เฉพาะโมดูลที่กดได้จริง**

  ไม่ได้ย่อของเดิมให้เล็กลง แต่เปลี่ยนหน้าที่: บนจอกว้างมันคือแผนที่ บนจอแคบ
  พื้นที่แนวนอนมีจำกัดจนต้องเลือกอย่างเดียว — เลือก "ปุ่มที่กดแล้วไปไหนได้"
  เพราะแถบล่างที่เต็มไปด้วยของกดไม่ได้คือแถบที่คนเลิกมองภายในวันเดียว

  อยู่ "ล่าง" ไม่ใช่ "บน" เพราะนิ้วโป้งเอื้อมถึงขอบล่างได้โดยไม่ต้องขยับมือที่จับเครื่อง
  ซึ่งสำคัญกว่าปกติที่นี่ เพราะพนักงานถือเครื่องมือเดียวขณะอีกมือถือจานอยู่

- **`(pos)/layout.tsx`** — `flex-col-reverse lg:flex-row`
  ใน DOM แถบโมดูลยังมาก่อนเนื้อหาเสมอ (ลำดับที่ถูกสำหรับ screen reader และปุ่ม tab)
  แล้วให้ CSS เป็นคนย้ายมันไปล่างจอ ไม่ใช่สลับลำดับใน DOM

- **`cart-panel.tsx` (ใหม่)** — ตะกร้าที่เปลี่ยนรูปร่างตัวเอง

  CLAUDE.md ห้ามแยกเมนูกับตะกร้าเป็นคนละหน้า จอแคบจึงไม่ทำเป็นลิงก์ไปหน้าตะกร้า
  แต่เป็น **แถบสรุปที่ปักอยู่ล่างตลอดเวลา** บอกจำนวนรายการกับยอดรวม แตะแล้วกางขึ้น
  — ตัวเลขบนแถบขยับทุกครั้งที่กดเพิ่มของ ซึ่งคือสิ่งที่กฎข้อนั้นต้องการจริง ๆ

  **เป็น element เดียวที่เปลี่ยนคลาสตัวเอง ไม่ใช่สองชุดสลับกันโชว์** เพราะ
  `children` คือตะกร้าที่มี `<form>` หลายใบอยู่ข้างใน ถ้า render สองชุดแล้วซ่อน
  ชุดหนึ่งด้วย CSS จะได้ `useActionState` เดินสองตัว ปุ่มที่ซ่อนอยู่ยังถูกนับเป็น
  submit target และ screen reader อ่านตะกร้าซ้ำสองรอบ

- แถบหมวดเมนูเพิ่ม `overflow-x-auto` (ร้าน 12 หมวดบนแท็บเล็ตแนวตั้งคือเคสปกติ)
- หัวจอตัด "จำนวนคน / เวลาเปิด / รหัส QR" ทิ้งบนจอแคบ เก็บ **ยอดสะสม + ไฟ realtime**
  ซึ่งเป็นสองอย่างที่พนักงานเหลือบมองทุกนาที

### จอครัว (KDS)

หัวจอย่อลง 66→58px และซ่อนชื่อ/ตำแหน่งบนจอแคบ แต่ **ไฟ "สดอยู่" ไม่เคยถูกซ่อน**
— มันคือสิ่งเดียวที่บอกครัวว่ากำลังมองของสดหรือภาพค้าง สำคัญกว่าชื่อคนกดเสียอีก
แท็บสถานีย่อ min-width 168→128px และเลื่อนแนวนอนได้อยู่แล้ว

### หน้าลูกค้า

`max-w-md` mobile-first อยู่แล้ว **ไม่ต้องแก้อะไรเลย** — ยืนยันด้วยการวัดจริง
ทั้งสี่ความกว้าง

## 3. บั๊กที่เจอและแก้ระหว่างทาง

### 3.1 แถบล่างโผล่บนจอกว้างเป็นแถบแดงตั้ง ⚠ (ผู้ใช้เห็นก่อน)

รอบแรกผมใส่คลาส `ink-row` ให้แถบล่างเพื่อให้ได้เส้นคั่น 2px แล้วสั่งซ่อนด้วย `lg:hidden`
**ซึ่งไม่ทำงาน**

```css
.pos-skin .ink-row { display: flex }   /* specificity 0-2-0 */
.lg\:hidden          { display: none }  /* specificity 0-1-0 → แพ้ */
```

ผลคือบนจอ 1440px มีแถบสีแดงตั้งอยู่ข้าง ๆ แถบซ้าย โดยที่ `tsc` และ `build`
ไม่ฟ้องอะไรเลย — **กับดักตระกูลเดียวกับ `.pos-skin *{border-radius:0}`
ที่ CLAUDE.md หัวข้อ 4 เตือนไว้**

แก้ด้วยการเขียนหน้าตาของ `ink-row` ด้วย utility ตรง ๆ (`flex gap-[2px]` + พื้นหมึก)
แทนการใช้คลาสของ design system แล้วหวังให้ utility ทับได้

> **กฎที่ได้จากเรื่องนี้:** ห้ามใช้คลาสของ design system (`ink-row`, `ink-grid`,
> `panel`, `btn`, `stepper`, `modal`) คู่กับ utility ที่แก้ `display` เช่น
> `hidden` / `lg:flex` — ถ้าจำเป็นต้องซ่อนตามขนาดจอ ให้ครอบด้วย `<div>` เปล่า
> แล้วซ่อนตัวครอบแทน หรือเขียนหน้าตาด้วย utility ล้วน
> ตรวจของเดิมทั้งโปรเจกต์แล้ว ไม่มีที่อื่นติดกับดักนี้

### 3.2 ช่องว่างของกริดโต๊ะเป็นแผ่นดำทึบ (มีมาก่อนแล้ว)

`.ink-grid` วาดเส้นด้วยการเอา "พื้นหมึกของตัวเอง" โผล่ผ่านช่อง `gap` ซึ่งสวย
เมื่อจำนวนช่องหารด้วยจำนวนคอลัมน์ลงตัว แต่โต๊ะ 5 ตัวในกริด 4 คอลัมน์ทำให้
ช่องที่เหลือของแถวสุดท้ายกลายเป็นแผ่นหมึกทึบค้างกลางจอ

เพิ่มคลาสเสริม **`.ink-grid-sparse`** ที่กลับวิธีวาดเส้น: พื้นกริดเป็นกระดาษ
แล้วให้แต่ละช่องวาดวงแหวนหมึก 1px รอบตัวเอง — ช่องที่ติดกันยิงวงแหวนเข้าหากัน
ในช่อง gap 2px จึงได้เส้นหนา 2px เท่าเดิมเป๊ะ ส่วนที่ไม่มีช่องก็ไม่มีใครวาด = กระดาษเปล่า

**เป็น opt-in ไม่ได้แก้ `.ink-grid` เดิม** เพราะแป้น PIN ใช้ `.btn-tile` ที่มี
`all: unset` ซึ่งจะล้าง `box-shadow` ทิ้ง — กริดที่เต็มอยู่แล้วไม่ต้องแก้อะไร
และไม่ควรเสี่ยงให้มันเปลี่ยนตาม

## 4. วิธีทดสอบ — วัดการล้นแนวนอนจริงด้วย headless Chrome

"Responsive" ที่ตรวจด้วยตาเปล่าคือการเดา สิ่งที่วัดได้จริงคือ
**`document.documentElement.scrollWidth > window.innerWidth` หรือเปล่า**
ซึ่งตรงกับอาการ "จอมันเลื่อนออกไปข้างขวาได้" ที่คนบ่นถึงพอดี

ขับ Chrome ผ่าน CDP ตรง ๆ ด้วย `WebSocket` ที่มีอยู่แล้วใน Node 24
**ไม่ต้องลง puppeteer/playwright เพิ่มเลย** (สคริปต์อยู่ใน scratchpad ของ session
ไม่ได้ commit เพราะเป็นเครื่องมือตรวจครั้งเดียว ไม่ใช่ของที่ต้องรันซ้ำทุกครั้ง)

```
เปิด chrome --headless=new --remote-debugging-port=9222
→ Network.setCookie (ใส่ cookie ของ POS / KDS / ลูกค้า)
→ Emulation.setDeviceMetricsOverride (390 / 768 / 1024 / 1440)
→ Runtime.evaluate วัด scrollWidth เทียบ innerWidth + หา element ที่ล้น
→ Page.captureScreenshot เก็บภาพไว้ดูด้วยตาอีกชั้น
```

ครอบ 8 หน้า × 4 ความกว้าง = **32 เคส ผ่านทั้งหมด (ล้น 0px)**

หน้าที่ตรวจ: `/pos`, `/pos/table/[id]`, `/pos/table/[id]?view=bills`, `/pos/login`,
`/kds`, `/kds/login`, `/t/[code]`, `/t/[code]/orders`

รอบแรกจับได้ 1 เคสที่ล้นจริง (`/kds/login` ที่ 1024px ล้น 78px) ซึ่ง
**เป็นเคสที่ไม่มีทางเจอด้วยการลากขอบเบราว์เซอร์ดู** เพราะล้นเฉพาะช่วงแคบ ๆ
รอบ ๆ 1024px เท่านั้น พอกว้างกว่านั้นก็หายไปเอง

## 5. ยังไม่ได้ทำ

- **แนวนอนบนมือถือ (landscape)** ยังไม่ได้ตรวจ — จอสูง 390px กับ `h-dvh`
  จะเหลือพื้นที่เนื้อหาน้อยมากหลังหักหัวจอ + แถบล่าง + แถบสรุปตะกร้า
- หน้า `/admin` ยังเป็นหน้าเปล่า (บทที่ 13)
- ยังไม่ได้ทำ automated visual regression — ถ้าอยากได้ ต้องเก็บภาพ baseline
  แล้วเทียบทุกครั้งที่แก้ UI ซึ่งเป็นงานคนละก้อน

**ก้อนถัดไปตามแผน = บทที่ 10 (คิดเงิน)** — `calculateBill` ด้วยจำนวนเต็มสตางค์
ลำดับ service charge → VAT
