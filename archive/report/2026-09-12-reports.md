## 2. การตัดสินใจที่สำคัญที่สุด

### 2.1 ยอดเงินมาจาก `Payment` · จำนวนชิ้นมาจากบิลที่ **จ่ายแล้ว**

**ต่างจากหน้า "สรุปวันนี้" โดยตั้งใจ** ซึ่งนับของที่ **ส่งเข้าครัวแล้ว** เพราะมันตอบ
คำถาม "ตอนนี้ครัวทำอะไรไปแล้วบ้าง" และช่วงเย็นที่ลูกค้ายังนั่งเต็มร้านจะดูเหมือน
ขายไม่ออกถ้านับเฉพาะบิลที่ปิด

รายงานย้อนหลังตอบคนละคำถาม: "ช่วงนั้นขายอะไรไปแล้วได้เงินเท่าไร" — ถ้านับของที่
ยังไม่จ่าย **ตารางเมนูกับยอดรายได้จะบวกไม่ตรงกัน** แล้วทั้งหน้าเชื่อไม่ได้

มีเทสต์ตรึงทั้งสองด้าน: บิลที่ยังไม่จ่ายไม่ขยับทั้งจำนวนชิ้นและรายได้ ·
รายการที่ถูกยกเลิกหลุดจากจำนวนชิ้น **แต่เงินที่รับไปแล้วยังอยู่ในรายได้**
(ยกเลิกรายการไม่ใช่การคืนเงิน)

### 2.2 จัดกลุ่มวัน/ชั่วโมงใน JS ไม่ใช่ SQL

เขตเวลาของสาขาเป็นข้อมูลในแอป (`Branch.timezone`) — group ใน SQL ต้องส่งชื่อโซน
เข้าไปแล้วหวังว่า tzdata ของ container ตรงกับของ Node = **สองแหล่งความจริง**

ราคาที่จ่าย: ต้องดึงแถว `Payment` ทั้งช่วงมาในหน่วยความจำ → **เพดาน 92 วัน**
**ห้ามเพิ่มตัวเลขนี้เฉย ๆ** ต้องย้ายการจัดกลุ่มไป SQL ก่อน

วันที่ไม่มียอดถูกเติมเป็น 0 เพราะกราฟแท่งที่ข้ามวันที่ร้านปิดจะอ่านผิด —
ดูเหมือนขายทุกวันทั้งที่หยุดไปหนึ่งวัน

### 2.3 ช่วงเวลาอยู่ใน URL ไม่ใช่ state

หน้านี้ต้องส่งลิงก์ให้กันได้ และ **ปุ่มส่งออกใช้พารามิเตอร์ชุดเดียวกัน** —
ถ้าเก็บใน state ปุ่มส่งออกจะต้องรู้ state นั้นด้วย ซึ่งเป็นสองแหล่งความจริงทันที

### 2.4 ส่งออกเป็น Route Handler ไม่ใช่ Server Action

action คืนค่าให้ React ไม่ได้คืน "ไฟล์ที่เบราว์เซอร์ต้องดาวน์โหลด" —
ต้องมี response จริงที่มี `Content-Disposition`

**ตรวจสิทธิ์ในไฟล์นั้นเองซ้ำอีกชั้น** เพราะ URL ยิงตรงได้จากแถบที่อยู่
· ตอบ **403 ไม่ใช่ redirect** เพราะปลายทางเป็นไฟล์ ไม่ใช่หน้า HTML
(เหตุผลเดียวกับที่ `/api/realtime` ตอบ 401 ในบทที่ 8)

### 2.5 CSV ต้องมี BOM

Excel เดา encoding ของ `.csv` จาก codepage ของเครื่อง ไม่ใช่ UTF-8 — ชื่อเมนู
ภาษาเวียดนามจะกลายเป็นอักษรขยะทันทีถ้าไม่มี BOM นำหน้า และ **ผู้ใช้จะสรุปว่า
"ระบบพัง" ไม่ใช่ "Excel เดาผิด"**

**ยอดเงินในไฟล์เป็นจำนวนเต็มหน่วยย่อยดิบ + บอกสกุลที่ชื่อคอลัมน์**
(`Doanh thu (VND)`) เพราะสเปรดชีตต้องบวกคอลัมน์นั้นได้ ส่วนการจัดรูปเป็นเรื่องของหน้าจอ

## 3. กับดักที่เจอจริง

### 3.1 ⚠ ตัวช่วยเรื่องเขตเวลาในเทสต์ที่เขียนผิด แล้วไปกล่าวหาโค้ดที่ถูก

รุ่นแรกของ `branchMidnightUtc()` ในสคริปต์เทสต์เทียบแค่ **วันที่**:

```ts
const shown = new Intl.DateTimeFormat("en-CA", { timeZone }).format(guess);
const drift = Date.parse(`${shown}T00:00:00Z`) - Date.parse(`${ymd}T00:00:00Z`);
```

ได้ `drift = 0` ทุกครั้งที่วันตรงกัน แล้วคืน `00:00Z` ซึ่งคือ **07:00 ตามเวลาเวียดนาม**
ผลคือ "23:59:30 ของวันนี้" กลายเป็นเช้าวันถัดไป → เทสต์ฟ้องว่าขอบช่วงของ
`getSalesReport()` ผิด ทั้งที่โค้ดจริงถูกมาตลอด

**แก้สองชั้น:** วัด offset จากเวลาเต็ม (ไม่ใช่แค่วัน) **และเพิ่มเคสที่ยืนยันว่า
เทสต์สร้างเวลาที่ตั้งใจได้จริง** ก่อนจะเอาไปใช้:

```
PASS  เทสต์สร้างเวลา 23:xx ของวันนี้ตามเวลาสาขาได้จริง — 2026-09-12 23
PASS  เทสต์สร้างเวลา 00:xx ของวันถัดไปตามเวลาสาขาได้จริง — 2026-09-13 00
```

> **บทเรียน:** เทสต์ที่สร้าง "เวลา" ขึ้นมาเองต้องพิสูจน์ก่อนว่าสร้างได้ถูก
> ไม่งั้นมันจะชี้ไปที่โค้ดที่ไม่ได้ผิด แล้วเสียเวลาไล่หาบั๊กที่ไม่มีอยู่

### 3.2 ⚠ เทสต์ที่เทียบค่าสัมบูรณ์พังทันทีที่ฐาน dev มีข้อมูลอื่น

เคสจำนวนชิ้นเขียนเทียบตรง ๆ (`itemsSold === 7`) ผ่านตอนเขียน แต่พอสร้างข้อมูลให้
หน้าจอมีของด้วย `dev:sell-bill` เพื่อไปวัดจอ **สี่เคสแดงทันที** (ได้ 11 กับ 9)

ตัวเลขรายได้ในไฟล์เดียวกันเขียนเทียบ baseline ไว้ถูกแล้ว แต่ตัวเลขจำนวนชิ้นลืม —
**เป็นบั๊กของเทสต์ ไม่ใช่ของโค้ด** (โค้ดนับบิลทุกใบในช่วงซึ่งถูกต้อง)

แก้เป็นวัดส่วนต่างจาก baseline ทั้งหมด — ตระกูลเดียวกับยอดเงินนอกกะใน `smoke:shift`
ที่เจอปัญหานี้มาก่อน **ชุดเทสต์ที่แตะข้อมูลร่วมต้องวัดส่วนต่างเสมอ**

### 3.3 proxy กันคนที่ไม่ได้ล็อกอินก่อนถึง Route Handler

ยิง `/admin/reports/export` โดยไม่มี cookie ได้ **307** ไม่ใช่ 403 เพราะ `proxy.ts`
redirect ไปหน้าล็อกอินก่อน — ไม่ใช่บั๊ก แต่แปลว่า **เทสต์สิทธิ์ที่มีความหมายจริง
คือคนที่ล็อกอินแล้วแต่ไม่มีสิทธิ์** (แคชเชียร์/ครัวเข้าจอ admin ได้) ซึ่งได้ 403 จริง

## 5. ที่ตั้งใจไม่ทำ

- **ต้นทุน · กำไรขั้นต้น · งบกำไรขาดทุน** — ต้องมี `costPrice` ที่ `MenuItem`
  (spec วางไว้ที่ §4 Product Management ไม่ใช่ §18) และโมดูลรายจ่ายซึ่ง
  **ไม่มีในแผนของ e-book เลย**
- **รายงานสต็อก** — บทที่ 14 ยังไม่มี ไม่มีตารางวัตถุดิบ
- **บรรทัด refund** — ระบบยังไม่มีการคืนเงิน · **ห้ามใส่คอลัมน์ที่เป็น 0 ตลอดกาล**
  (กฎเดิมจากบทที่ 15) หน้าจอเขียนบอกตรง ๆ ว่ายังไม่มีและเพราะอะไร
- **Excel / PDF** — เพิ่ม dependency ทั้งคู่ · CSV เปิดใน Excel ได้อยู่แล้ว
- **ไลบรารีกราฟ** — แถบสัดส่วนวาดด้วย `div` กว้างเป็น % พอ และไม่ต้องดูแล
  ธีม/ภาษา/ขนาดจอของไลบรารีเพิ่ม
- **ไม่เพิ่มโมดูลที่เจ็ดในแถบหลังร้าน** — ทางเข้าคือลิงก์จากหน้าสรุปวันนี้
  (ท่าเดียวกับประวัติกะ · แถบล่างที่ 390px เหลือช่องละ ~55px)
