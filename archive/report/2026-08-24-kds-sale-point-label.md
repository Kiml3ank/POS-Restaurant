## 1. ปัญหาที่ก้อนนี้แก้

ก่อนมีช่องทางซื้อกลับ ทุกบิลอยู่บนโต๊ะ โค้ดทั่วระบบจึงเขียน `table.name` ตรง ๆ
แล้วแปะคำว่า "โต๊ะ" ไว้ข้างหน้า พอเปิดใช้เคาน์เตอร์ ผลที่ออกมาคือ

```
เคาน์เตอร์ซื้อกลับ          ← ตั๋วครัว: ทุกใบเขียนเหมือนกันหมด อ่านแล้วไม่รู้ว่าของใคร
โต๊ะ: เคาน์เตอร์ซื้อกลับ    ← ใบเสร็จ: เรียกสิ่งที่ไม่ใช่โต๊ะว่าโต๊ะ
```

ผิดคนละแบบ: อันแรกบอก **ชื่อช่อง** แทนที่จะบอกว่าเป็นบิลของใคร (ร้านมีเคาน์เตอร์เดียว
แต่ลูกค้าหลายคน) อันที่สองเรียกชื่อผิดประเภท — สิ่งที่ต้องบอกคือ **เลขคิว**

## 2. กฎใหม่ที่รวมไว้ที่เดียว (`lib/sale-point.ts`)

- **`salePointDisplayName(table, session)`** — ชื่อที่ใช้เรียกบิลใบหนึ่งบนจอ กระดาษ
  และตั๋วครัว **ที่เดียวในระบบ** · โต๊ะนั่ง → `โต๊ะ A2` · ที่เหลือ → `ซื้อกลับ คิว 12`
  · ไม่มีเลขคิว (ข้อมูลก่อนมีคอลัมน์นี้) → ตกกลับไปใช้ชื่อจุดขาย ไม่ใช่ `คิว null`
  **กฎตัดสินที่ `kind` ไม่ใช่ที่ "มีเลขคิวไหม"** — โต๊ะที่มีเลขคิวติดมาก็ยังอ่านว่าโต๊ะ
- **`salePointFieldLabel(kind)`** — ป้ายของช่องข้อมูลบนใบเสร็จ (`โต๊ะ` / `ช่องทาง`)
  แยกจากตัวบน เพราะบางที่ต้องการป้ายกับค่าแยกกัน (`<dt>` กับ `<dd>`)
- **`salePointBasePath(table, session)` (ใหม่ในก้อนนี้)** — ที่เดียวที่ตัดสินว่า
  บิลนี้อยู่ URL ตระกูลไหน: โต๊ะชี้ด้วย `tableId` · ช่องทางอื่นชี้ด้วย `sessionId`
  เดิมกฎนี้เป็นฟังก์ชันส่วนตัวใน `app/(pos)/pos/actions.ts` ซึ่งเป็นไฟล์ `"use server"`
  ที่ **export ค่าที่ไม่ใช่ async function ออกมาไม่ได้** หน้าอื่นจึงเขียนเส้นทางเองแล้วผิด

## 4. สามจุดที่หลุด และเจอเพราะ "ไปอ่าน HTML ของจอจริง" ไม่ใช่เพราะเทสต์

เทสต์ทุกชุดเขียวอยู่แล้วตอนที่สามจุดนี้ยังผิด:

1. **หัวจอหน้าใบเสร็จ (ทั้ง POS และหลังร้าน) ยังเขียน `โต๊ะ {table.name}`**
   → กระดาษถูก แต่แถบหัวจอเหนือกระดาษยังอ่านว่า "โต๊ะ เคาน์เตอร์ซื้อกลับ"
2. **ลิสต์ใบเสร็จหลังร้านเติมคำว่า "โต๊ะ " ซ้ำ** — `row.tableName` มีคำนำหน้าของตัวเอง
   มาแล้ว ผลคือ "โต๊ะ โต๊ะ A1" และ "โต๊ะ ซื้อกลับ คิว 1"
3. **ปุ่ม "กลับไปสรุปการรับเงิน" บนหน้าใบเสร็จพาไป `/pos/table/<counterId>/...` เสมอ**
   — เป็นบั๊กเงียบชนิดที่หน้าเปิดได้ 200 เหมือนกัน แต่พนักงานไปยืนอยู่บนเส้นทาง
   ตระกูลโต๊ะทั้งที่ถือบิลซื้อกลับ (ปุ่มรองก็ยังเขียนว่า "ผังโต๊ะ" ทั้งที่ควรเป็นแถบคิว)

**บทเรียนเดิมซ้ำเป็นครั้งที่สาม:** เทสต์ที่ถามว่า "ฟังก์ชันคืนค่าถูกไหม" ตอบว่าถูกได้
ตลอดในขณะที่ **จอ** ยังผิด เพราะจอมีข้อความที่เขียนมือค้างอยู่คนละที่กับฟังก์ชัน

## 5. บั๊กที่ใหญ่กว่าป้ายชื่อ — ครัวไม่เห็นออร์เดอร์ที่ลูกค้าจ่ายเงินแล้ว

ระหว่างตรวจจอครัวบนเซิร์ฟเวอร์จริงพบว่าตั๋วหายทั้งที่ของยังไม่ได้ทำ ไล่ดูแล้วได้ตัวเลขนี้:

```
ก่อนจ่าย: order=PLACED · ตั๋วบนจอครัว=มี
หลังจ่าย: order=PAID   · รายการ=PLACED · ตั๋วบนจอครัว=ไม่มี
```

`getKitchenTickets()` กรอง `Order.status in (PLACED, IN_PROGRESS, READY)` แต่การรับเงิน
ตั้งบิลเป็น `PAID` ทันที **ตั๋วจึงหลุดจากจอครัวตอนกดรับเงิน ทั้งที่ครัวยังไม่ได้ทำอะไรเลย**

- CLAUDE.md บทที่ 11 เขียนไว้ว่า "ของที่ยังไม่ได้ทำยังอยู่บนจอครัวต่อไปแม้บิลจะ PAID"
  — **ข้อความนั้นบรรยายสิ่งที่โค้ดไม่ได้ทำ** (กรองสองชั้น ชั้นบิลตัดทิ้งก่อน)
- อาการหนักที่สุดคือเคาน์เตอร์ซื้อกลับ ซึ่ง **จ่ายก่อนแล้วยืนรอเป็นลำดับปกติ**
  = ลูกค้าจ่ายเงินแล้วแต่ครัวไม่เคยเห็นออร์เดอร์นั้น
- โต๊ะนั่งก็โดนเหมือนกันเมื่อลูกค้าขอจ่ายก่อนของครบ

**แก้:** เปลี่ยนตัวกรองเป็น `status notIn (DRAFT, CANCELLED)` — ตัดเฉพาะตะกร้าที่ยังไม่ส่ง
กับบิลที่ยกเลิก ส่วนบิลที่ทำครบแล้วหลุดจากจอเองอยู่แล้วเพราะรายการพ้น
`KITCHEN_ITEM_STATUSES` **งานครัวจบที่ระดับ "รายการ" เสมอ ไม่ใช่ที่ระดับ "บิล"**
(เขียนคำเตือนกำกับไว้ในโค้ดแล้วว่าห้ามกลับไปกรองด้วยสถานะบิล)

## 6. เทสต์ที่เพิ่ม (`smoke:takeaway` 59 → 75 เคส)

หัวข้อใหม่ "7. ชื่อบิลบนตั๋วครัวและใบเสร็จ" + สองเคสในหัวข้อรับเงิน:

- ป้ายของทั้งสามช่องทาง · เคสไม่มีเลขคิว · เคสโต๊ะที่มีเลขคิวติดมา · `salePointFieldLabel`
- **ตั๋วครัวจริงจาก `getKitchenTickets()`** ไม่ใช่แค่ฟังก์ชันแปลงป้าย — ถ้า query ลืม
  select `queueNumber` ฟังก์ชันจะยังผ่านหมดแต่จอจริงตกไปใช้ชื่อช่องทั้งวัน
- เส้นทางฐานของทั้งสองตระกูล URL (`/pos/table/<id>` vs `/pos/counter/<sessionId>`)
- **ชื่อบิลบนใบเสร็จ** ผ่าน `listReceipts()` (ต้องเปลี่ยนคนถามเป็น OWNER เพราะ
  `canBrowseReceipts` ไม่ใช่สิทธิ์ของแคชเชียร์)
- **"จ่ายเงินแล้วแต่ครัวยังไม่ได้ทำ = ตั๋วยังอยู่บนจอครัว"** — เคสที่แดงก่อนแล้วค่อยแก้โค้ด

**พิสูจน์ว่าเทสต์กัดจริง (mutation test):** ย้อน `salePointDisplayName()` กลับไปเป็น
พฤติกรรมเดิมชั่วคราว → FAIL 4 เคสทันที (รวมเคสที่อ่านจากตั๋วจริง) แล้วคืนโค้ดกลับ

## 8. ยังไม่ได้ทำ

- **ช่องค้นหาในลิสต์ใบเสร็จยังค้นด้วย "ชื่อโต๊ะ" เท่านั้น** — พิมพ์ "คิว 12" หาใบของ
  ลูกค้าซื้อกลับไม่เจอ (ต้องใช้เลขที่ใบแทน) · ป้ายใต้ช่องยังเขียนว่า "เลขที่ใบ หรือชื่อโต๊ะ"
- ฟอร์มกรอกชื่อลูกค้าซื้อกลับ (`TableSession.customerName` มีคอลัมน์+แสดงผลแล้ว)
- ไรเดอร์ทั้งหมด · ยังไม่ได้วัด responsive/overflow ของสองหน้าใหม่ด้วยสคริปต์ headless
