## 2. ⚠ งานถัดไปที่ **ออกแบบเสร็จแล้วแต่ยังไม่ได้เขียนโค้ด** — แยกบิล

ผู้ใช้อนุมัติทิศทางแล้วในรอบนี้ แต่สั่งพักก่อนเริ่มลงมือ **บันทึกไว้ที่นี่เพราะยัง
ไม่มี spec/plan เป็นไฟล์** (ถ้าทำต่อ ให้เขียน spec + plan ตามคอนเวนชันก่อน)

### 2.1 กลไก: "จ่ายบางส่วน" ไม่ใช่ entity ใหม่

`TableSession.payments` เป็น `Payment[]` อยู่แล้ว และ `distributeByWeight()` ใน
`lib/bill.ts` มีอยู่แล้ว — **สิ่งที่ขวางการแยกบิลตอนนี้คือบรรทัดเดียว** ใน
`takePayment()` ที่ปิดรอบโต๊ะเป็นคำสั่งแรกของทรานแซกชัน (ซึ่งเป็นด่านกันจ่ายซ้ำ
ของบทที่ 11 — `lib/server/payment.ts:207`)

สิ่งที่ต้องเปลี่ยน: **จ่ายได้บางส่วน และรอบโต๊ะปิดเมื่อยอดค้างเหลือศูนย์เท่านั้น**

เหตุผลที่เลือกทางนี้แทนการสร้างตาราง "บิลย่อย": ใบเสร็จ · ยอดเงินสดในกะ ·
รายงานยอดขาย **ทุกตัวรวมจากแถว `Payment` อยู่แล้ว** จึงไม่ต้องแก้อะไรเลยสักที่

### 2.2 สองวิธีแยก แต่กลไกเดียว

- **หารเท่ากัน N ทาง** — หน้าจอคำนวณ N ส่วนด้วย `distributeByWeight()` ให้บวกกลับ
  ได้พอดี แล้วรับเงินทีละส่วนเป็น `Payment` ของตัวเอง
- **ระบุจำนวนเงิน** — "ใบนี้รูดบัตร 200.000 ₫" ที่เหลือค้างไว้

**แยกตามรายการ (by item) ตั้งใจไม่ทำ** — เป็นคนละโมเดลข้อมูล ต้องผูกทุกรายการ
เข้ากับบิลย่อย มี UI ของตัวเอง และต้องมีกติกาสำหรับของที่แชร์กัน (ส้มตำจานเดียว
สามคนกิน) · ควรเป็นก้อนแยกถ้าจะทำ — **ผู้ใช้ยังไม่ได้ตอบว่าจะเอาหรือไม่**

### 2.3 ส่วนย่อยต้องบวกกลับได้เท่ายอดเต็ม

`Payment` แต่ละแถว snapshot `subtotal`/`serviceChargeAmount`/`vatAmount`/`grandTotal`
— ของการจ่ายบางส่วนต้องเป็น **สัดส่วนของก้อนนั้น** แจกด้วย largest-remainder
**ห้ามคิดภาษี/ค่าบริการใหม่ทีละใบ** ไม่งั้นสามใบของบิล 132.000 จะบวกกลับไม่ได้ 132.000
(กับดักเดียวกับที่บทที่ 11 เจอตอนกระจายยอดลง `Order`)

### 2.4 จุดที่เสี่ยงที่สุดคือการชนกัน

แคชเชียร์สองเครื่องรับสองส่วนสุดท้ายพร้อมกัน **ต้องไม่ปิดรอบโต๊ะทั้งคู่ และต้องไม่
คิดว่าตัวเองกำลังจ่ายยอดค้างก้อนเดียวกัน** → คิดยอดค้าง **ในทรานแซกชัน** และ
การปิดยังเป็น conditional update เหมือนเดิม (ท่าเดียวกับปิดกะในบทที่ 15)

### 2.5 ผลที่ตามมาที่ต้องบอกผู้ใช้บนจอ

- หน้าบิลต้องมีบรรทัด **"จ่ายแล้วเท่าไร / ค้างเท่าไร"** และปุ่มแยกบิล
- `expectedTotal` ที่หน้าจอแนบมาเปลี่ยนเป็น **ยอดค้างที่คาดไว้** เพื่อให้บิลที่
  เปลี่ยนกลางคันยังถูกปฏิเสธเหมือนเดิม
- **แยกสามทาง = ออกใบกำกับภาษีสามใบ** (คนจ่ายแต่ละคนได้ใบของตัวเอง ซึ่งถูกต้อง)
  แปลว่า **เลขใบเสร็จเดินไปสามเลข** — ต้องเขียนบอกบนปุ่มแยกบิล ไม่ให้คนกดตกใจ

### 2.6 สิ่งที่ต้องระวังเพิ่มตอนลงมือ

- กฎเดิมยังอยู่: **ตะกร้า `DRAFT` ที่มีของ = จ่ายไม่ได้** (บทที่ 11)
- `getSessionBill()` ตอนนี้ยังไม่รู้จักยอดที่จ่ายไปแล้ว — ต้องเพิ่ม
- `closeTableSession()` ของ `lib/server/pos.ts` ปฏิเสธรอบที่มีของเข้าครัวแล้ว
  ตรวจด้วยว่าตรรกะนั้นยังถูกเมื่อมีการจ่ายบางส่วนค้างอยู่
