## 1. ฟอร์มกรอกชื่อลูกค้า

`TableSession.customerName` มีคอลัมน์และมีที่แสดงผลมาตั้งแต่ก้อนก่อน แต่ไม่มีทางกรอก

- **`setSessionCustomerName()` ใน `lib/server/pos.ts`** — ตั้งได้เฉพาะรอบที่ **ยังเปิดอยู่**
  ในสาขาของพนักงานคนนั้น · ส่งค่าว่างมา = **ล้างเป็น `null` ไม่ใช่สตริงว่าง**
  (ทุกที่ที่แสดงผลเช็คด้วย `customerName ? …` สตริงว่างจะกลายเป็นบรรทัดเปล่า)
  · ยาวเกิน 40 ตัวอักษร = ปฏิเสธ · **โต๊ะนั่งตั้งไม่ได้** เพราะชื่อโต๊ะทำหน้าที่นี้อยู่แล้ว
  และช่องกรอกที่ไม่มีใครใช้คือช่องที่พนักงานจะกรอกอะไรก็ได้ลงไป
- **ไม่เขียน `AuditLog`** เพราะไม่แตะเงินและไม่ใช่สิทธิ์พิเศษ — ต่างจากส่วนลดพนักงาน
  ที่ต้องมีทุกครั้ง (`lib/server/staff-meal.ts`)
- **รอบที่ปิดไปแล้วแก้ชื่อไม่ได้** — ไม่งั้นชื่อบนใบเสร็จที่พิมพ์ไปแล้วกับชื่อในฐานข้อมูล
  จะไม่ตรงกันโดยไม่มีร่องรอยว่าใครแก้ตอนไหน (มีเคสตรึงไว้)

**ที่วางฟอร์ม: แท็บ "บิลที่ส่งแล้ว" ไม่ใช่ตะกร้าหรือหัวจอ** — เพราะโซนนั้นเป็นโซนที่
**เลื่อนได้** ส่วนตะกร้ากับหัวจอเป็น `flex-none` และกฎที่ CLAUDE.md บันทึกไว้หลังบั๊ก
"รวมทั้งสิ้นหายจากจอ" คือ *อะไรที่เพิ่มในโซน `flex-none` จะไปกินพื้นที่ของโซนที่เลื่อนได้เสมอ*
· ปุ่มเดียวทำได้ทั้งตั้งและล้างชื่อ (ส่งช่องว่าง = ล้าง) จึงไม่มีปุ่มลบให้กดผิด

## 2. ค้นใบเสร็จด้วยเลขคิว

ลูกค้าซื้อกลับที่เดินกลับมาถามถึงใบเสร็จพูดว่า **"คิว 12"** ไม่ใช่เลขที่ใบ และบิลซื้อกลับ
ไม่มีชื่อโต๊ะให้ค้น — เดิมจึงต้องไล่เปิดดูทีละใบ

- `listReceipts()` ดึงเฉพาะตัวเลขออกจากคำค้น จึงพิมพ์ได้ทั้ง `12` และ `คิว 12`
- **เลขที่ยาวเกินช่วง `Int` ต้องตัดทิ้งก่อน** ไม่ใช่ส่งให้ฐานข้อมูลไปพัง — คนที่พิมพ์
  เลขที่ใบแบบไม่มีขีดจะได้เลขยาวแบบนั้นพอดี (มีเคสตรึงว่าค้นด้วยเลขที่ใบยังทำงานเหมือนเดิม)
- ป้ายใต้ช่องเปลี่ยนเป็น "เลขที่ใบ · ชื่อโต๊ะ · เลขคิว" ให้ตรงกับสิ่งที่ค้นได้จริง

**⚠ บั๊กที่เทสต์จับได้ทันที:** รอบแรก regex ในโค้ดกลายเป็น `/d+/` (backslash หายไป
ตอน patch ไฟล์) ซึ่ง **ไม่มี error ใด ๆ ทั้ง tsc/eslint/build** — ค้นแล้วไม่เจอเงียบ ๆ
เท่านั้น เคส "ค้นด้วย 'คิว N' ต้องเจอ" คือสิ่งเดียวที่จับได้

## 3. วัดจอจริง + เครื่องมือใหม่ `npm run audit:screens`

สคริปต์วัดของบทที่ 9 เป็นของชั่วคราวที่ไม่ได้ commit และวัด **แนวนอนอย่างเดียว**
ซึ่งปล่อยบั๊กผ่านมาแล้วสองครั้ง (`sr-only` ดันทั้งหน้าให้เลื่อนได้ · flexbox บีบโซน
ที่เลื่อนได้จนยอด "รวมทั้งสิ้น" หายจากจอ) คราวนี้ทำเป็นเครื่องมือถาวรที่วัดสี่อย่าง:

| วัดอะไร | จับบั๊กแบบไหน |
|---|---|
| `scrollWidth > innerWidth` | เนื้อหาล้นออกข้างขวา |
| `scrollHeight > innerHeight` | มีของทะลุเชลล์ `h-dvh overflow-hidden` ออกไปดันความสูง |
| ของที่ "ต้องเห็น" เทียบกับ **กรอบของกล่องที่เลื่อนได้** | ตัวเลขสำคัญถูกกล่องแม่ตัดทิ้ง |
| โซน `overflow-auto` ที่สูง < 96px ทั้งที่เนื้อในยาวกว่าเท่าตัว | โซนเลื่อนถูก flexbox บีบจนแบน |

ขับ Chrome ผ่าน CDP ด้วย `WebSocket` ที่มีใน Node เอง — **ไม่ต้องลง puppeteer**
· รับหน้าที่จะวัดกับ cookie ผ่าน env (`AUDIT_PAGES` / `AUDIT_COOKIES` / `AUDIT_ORIGIN`)
· **ต้องวัดกับ `npm run build` + `npm run start` เสมอ ไม่ใช่ dev server**

## 4. ยังไม่ได้ทำ

- **ไรเดอร์ทั้งหมด** (`/pos/delivery`, `PaymentMethod.PLATFORM`, `platformOrderCode`)
- ชื่อลูกค้ายัง **ไม่ขึ้นบนตั๋วครัว** — ครัวเห็นแค่ "ซื้อกลับ คิว 12" ตามกฎ
  `salePointDisplayName()` (ถ้าจะเพิ่ม ต้องตัดสินใจว่าเป็นบรรทัดที่สองของตั๋ว
  ไม่ใช่ไปต่อท้ายป้ายชื่อบิล ซึ่งจะทำให้กฎการเรียกชื่อบิลมีสองแบบ)

  — เครื่องมือพร้อมแล้ว เหลือแค่ใส่รายการหน้าเข้าไป
