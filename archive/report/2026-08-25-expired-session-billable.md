## 1. บั๊ก: ตั๋วค้างบนจอครัวโดยไม่มีบิลให้คิดเงิน (บั๊กหลักของก้อนนี้)

### อาการที่ผู้ใช้เจอ

จอครัวมีกะเพรา `READY` ค้างอยู่หนึ่งรายการ แต่หาบิลของมันไม่เจอจากหน้าจอไหนเลย
ทั้งผังโต๊ะและแถบคิวซื้อกลับ

### รากของปัญหา

`TableSession.expiresAt` (TTL 3 ชม.) **เป็นด่านของลูกค้าอย่างเดียว** — มีไว้กันเคส
"ถ่ายรูป QR ไว้แล้วสั่งจากบ้านอีกสามวันถัดมา" ตามที่คอมเมนต์ใน `table-session.ts`
เขียนไว้ตั้งแต่บทที่ 5

แต่มันหลุดไปอยู่ใน query **ฝั่งพนักงาน** ด้วยทั้งหมด 6 จุด ผลคือพอรอบโต๊ะครบ 3 ชม.
**บิลที่ยังไม่จ่ายจะหายไปจากสายตาพนักงานทั้งหมด**:

| จอ | เดิมกรอง | ผลกับโต๊ะ A1 |
|---|---|---|
| ผังโต๊ะ (`getPosTables`) | `status OPEN AND expiresAt > now()` | โต๊ะขึ้นว่า **ว่าง** |
| หน้าคิดเงิน (`getTableBill`) | เหมือนกัน | **ไม่มีบิล** |
| จอครัว (`getKitchenTickets`) | ไม่กรองอะไรเลย | **ตั๋วยังอยู่** |

แล้วกลายเป็นวงปิดที่ออกไม่ได้เลย:

1. ครัวกดต่อไม่ได้ — ของเป็น `READY` แล้ว และครัวเดินได้แค่ `PLACED → IN_PROGRESS → READY`
2. เสิร์ฟกด "เสิร์ฟแล้ว" ไม่ได้ — ปุ่มอยู่บนหน้าโต๊ะที่เข้าไม่ถึง
3. คิดเงินไม่ได้ — `getTableBill()` บอกว่าไม่มีบิล
4. `closeTableSession()` ก็ปิดไม่ได้ — มีของเข้าครัวไปแล้ว มันจึงบอกให้ "ไปคิดเงินก่อน"
   ซึ่งคือข้อ 3 ที่ปฏิเสธไปแล้ว

**ตระกูลเดียวกับบั๊ก "บิลที่มีน้ำเปล่าปนอยู่จะคิดเงินไม่ได้ตลอดกาล" ในบทที่ 8**
คือบิลที่ไม่มีวันปิดได้ ต่างกันที่คราวนี้ตัวจุดชนวนคือ **เวลา** ไม่ใช่ชนิดของสินค้า

### สิ่งที่แก้

**กฎใหม่: `expiresAt` กรองได้ที่เดียวคือด่านของลูกค้า — ฝั่งพนักงานห้ามกรอง**

ตัดตัวกรองออก 7 จุด:

- `lib/server/pos.ts` 5 จุด (`getPosTables`, `getPosTable`, `getPosSession`,
  `getOpenSalePointSessions`, `openSessionCount` ใน `buildPosDetail`)
- `lib/server/billing.ts` 1 จุด (`getTableBill`)
- `lib/server/table-session.ts` 1 จุด — `openOrJoinTableSession()`

**⚠ จุดที่ 7 สำคัญกว่าที่เห็น** ถ้าไม่แก้ด้วย จะเกิด **สองรอบที่ `OPEN` พร้อมกัน
บนโต๊ะนั่งตัวเดียว** (รอบเก่าหมดอายุ → พนักงานเปิดโต๊ะใหม่ → สร้างรอบที่สอง)
ซึ่งพังทั้งระบบ เพราะทุกที่ที่หารอบของโต๊ะใช้ `findFirst(orderBy openedAt desc)`
จึงเห็นแต่ใบใหม่ ส่วนใบเก่า **มองไม่เห็นแต่ยังบล็อกการคิดเงิน** — บั๊กตระกูลเดียวกับ
ที่เคาน์เตอร์ซื้อกลับเจอตอนทำบทซื้อกลับ

**ที่ไม่แตะ:** `resolveSessionByToken()` (`table-session.ts:124`) ยังกรอง `expiresAt`
เหมือนเดิม — นั่นคือที่ที่ถูกต้องของด่านนั้น รูโหว่ QR-ถ่ายรูปยังปิดอยู่

### เทสต์

เพิ่ม 5 เคสใน `npm run smoke:bill` (43 → 48) ตรึงไว้ **ทั้งสองด้าน**:

- รอบที่หมดอายุแล้วยัง `getTableBill()` ได้ · ยอดยังครบ · เปิดหน้าโต๊ะได้ · ผังโต๊ะยังเห็น
- **`resolveSessionByToken()` ยังคืน `null`** ← ถ้าเคสนี้กลายเป็น resolve เมื่อไหร่
  แปลว่ารูโหว่ QR กลับมาแล้ว

ยืนยันว่าเทสต์จับบั๊กจริง: รันก่อนแก้ได้ FAIL 4 PASS 1 (เคสลูกค้าผ่านอยู่แล้ว)

### ยืนยันกับของจริง

## 2. แถบข้าง POS: ซ่อนโมดูลที่กดไม่ได้

`app/(pos)/pos/_components/pos-sidebar.tsx`

**กฎใหม่: กดไม่ได้ = ไม่ต้องอยู่บนแถบ** — แสดงเฉพาะแถวที่มี `href`

- `todo` (05 สต็อก · 06 รายงาน) — ยังไม่ได้ทำ
- `hint` (03 คิดเงิน) — **ทำเสร็จแล้ว** แต่ไม่มี URL ของตัวเอง เพราะบิลผูกกับรอบโต๊ะ
  ต้องเลือกโต๊ะก่อน จึงเข้าจากโมดูล 01

**แถวใน `MODULES` ยังอยู่ครบ ไม่ได้ลบ** — เติม `href` ให้แถวไหนแล้วแถวนั้นจะโผล่เอง
(ยังเป็นที่เดียวที่ต้องแก้เหมือนเดิม) · เหลือบนจอ: 01 · 02 · 04

**หมายเหตุ:** แถบของ **หลังร้าน** (`admin-nav.tsx`) ยังมีกล่อง "Not built yet"
ที่ลิสต์สต็อก/รายงานอยู่ — ก้อนนี้แค่แปลเป็นอังกฤษ ยังไม่ได้ซ่อน (ผู้ใช้ขอเฉพาะ POS)

## 3. i18n: `/admin/menu` เป็นอังกฤษ

ตามคอนเวนชันของ commit i18n ก่อนหน้า: **แปลเฉพาะข้อความที่ผู้ใช้เห็น คอมเมนต์คงเป็นไทย**

- `app/(admin)/admin/menu/page.tsx` — หัวจอ · ปุ่ม · empty state · ป้ายสถานี
  (เพิ่มการแยกเอกพจน์/พหูพจน์: `1 item` / `2 items`, `1 category` / `4 categories`)
- `app/(admin)/admin/_components/admin-nav.tsx` — ป้าย 7 โมดูล + `short` + `hint`
  + "Back to POS" + กล่อง "Not built yet"
- `app/(admin)/layout.tsx` — "Back office" · "Full edit access / Sold-out toggle only" · "Lock screen"
- `components/live-refresh.tsx` — "Live / Connecting… / Disconnected" (ใช้ร่วมทุกจอ)
- `app/layout.tsx` — `<title>` + description
- `app/(pos)/pos/_components/bill-screen.tsx` — escape `'` เป็น `&apos;`
  (**lint พังอยู่ก่อนแล้วบน branch นี้** จาก i18n ก้อนก่อน ไม่ใช่ของก้อนนี้)

**ที่เหลือเป็นไทยบนหน้านั้นคือ "ข้อมูลใน DB" ไม่ใช่ UI** — ชื่อเมนู (ข้าวผัดกะเพราหมูสับ)
ชื่อหมวด (ของหวาน · ต้ม/แกง) ชื่อสถานี (ครัวร้อน) ชื่อสาขา ชื่อพนักงาน
จะเปลี่ยนต้องแก้ `prisma/seed.ts` หรือแก้ผ่านหน้าจอ **ไม่ใช่งาน i18n**
