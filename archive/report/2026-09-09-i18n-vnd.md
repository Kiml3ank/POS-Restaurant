### 2.2 กฎที่สำคัญที่สุดของก้อนนี้

> **`lib/server/*` ไม่แปลภาษา — คืน `errorKey` + `params` เท่านั้น หน้าจอเป็นคนแปล**

ผลสามอย่าง:

1. ข้อความ error เปลี่ยนภาษาตามปุ่มจริง ไม่ค้างในภาษาที่เซิร์ฟเวอร์เลือกไว้ตอนนั้น
2. **smoke ตรวจคีย์ ไม่ตรวจประโยค** — รากของบั๊กที่ทำให้เทสต์ 11 เคสพังตอนแปลเป็น
   อังกฤษรอบก่อน จะไม่เกิดอีก
3. `cookies()` ไม่หลุดเข้าไปในชั้นธุรกิจ ซึ่งรันในสคริปต์ที่ไม่มี request context

กฎรองที่ตามมา:

- **พจนานุกรมครบคู่เป็น compile error ไม่ใช่เทสต์** — พิสูจน์แล้วด้วยการลบคีย์ทิ้ง
  หนึ่งตัวแล้วดู `TS2741` ไม่ได้เชื่อว่ามันทำงาน
- **`countKey()` ให้ชั้นธุรกิจเลือกรูปเอกพจน์/พหูพจน์เอง** เพราะมันเป็นฝ่ายที่รู้จำนวน
- **ห้ามแทรกชื่อฟิลด์เป็น `{label}`** ถ้าชื่อฟิลด์นั้นต้องแปลเอง — `invalidRate()`
  รับคีย์ต่อฟิลด์เข้ามา และ `loadMovableSession()` เอาป้าย source/target ไปเป็น
  **ส่วนหนึ่งของคีย์** เพราะตอนกดรวมบิลผู้ใช้ต้องรู้ว่าบิลไหนที่ติดปัญหา
- **`salePointDisplayName()` ออกจาก `lib/server` แล้ว** — `listReceipts()` คืนชิ้นส่วน
  (`tableName` / `kind` / `queueNumber`) ให้หน้าจอประกอบชื่อเอง

## 3. กับดักที่เจอจริง (เรียงตามความสำคัญ)

### 3.1 `.pos-skin` specificity กินคลาสซ่อน/แสดงของ Tailwind — อีกครั้ง

กฎของ design system เขียนเป็น `.pos-skin .xxx` = specificity 0-2-0 ซึ่งชนะ utility
คลาสเดียว (0-1-0) แปะ `sm:hidden` ที่ตัวปุ่มสลับภาษาตรง ๆ จึงไม่มีผล

**แก้ด้วยการซ่อนที่ `<div>` ครอบ ไม่ใช่ที่ตัวปุ่ม** — ทำแบบเดียวกันทั้งสามเชลล์
(`hidden flex-none sm:block`) จอที่แคบกว่า `sm` สลับภาษาได้ที่หน้าล็อกจอแทน

เป็นกับดักตระกูลเดียวกับ `.pos-skin *{border-radius:0}` และเคส `<nav className="ink-row lg:hidden">`
ที่เคยโดนมาแล้ว — **ครั้งที่สามของโปรเจกต์นี้**

### 3.2 ปุ่มที่เพิ่มเข้าแถบหัวจอล้นกล่อง โดยที่ตัววัดเดิมมองไม่เห็น

เชลล์เป็น `overflow-hidden` แถบหัวจอที่ล้นจึงถูก **ตัดทิ้งเงียบ ๆ** โดย document
ไม่กว้างขึ้นเลย — การวัดข้อ 1 (ล้นแนวนอน) ตอบ "ไม่ล้น" ได้เสมอ และแถบที่
`justify-end` จะล้นไป **ทางซ้าย** ทับชื่อจอ ซึ่งไม่หลุดขอบจอด้วยซ้ำ

เจอจริงตอนวางปุ่มสลับภาษาบนแถบจอครัว: ที่ 390px ล้น 74px ทั้งที่การวัดข้อ 1-4 ผ่านหมด

→ **เพิ่มการวัดข้อ 5 เข้า `scripts/audit-screens.mjs`**: เดินทุกลูกใน `<header>`/`<nav>`
แล้วถามว่ายื่นออกนอกกล่องแม่หรือเปล่า (ข้ามแถบที่ตั้งใจให้เลื่อนแนวนอน)

### 3.3 ภาษาเวียดนามยาวกว่าอังกฤษ — แต่ครั้งนี้อังกฤษเป็นฝ่ายพัง

คาดไว้ว่าเวียดนามจะยาวกว่า ("Đã gửi bếp" vs "Placed") แต่ของที่พังจริงคือ
**แถบล่างของจอหลังร้านตอนเป็นภาษาอังกฤษ**: คำว่า "Settings" ถูกตัดที่ 390px
เพราะแถบมีเจ็ดช่อง (หน้าแรก + หกโมดูล) บวกปุ่มกลับ

→ แถบล่างเป็น `overflow-x-auto` + เลื่อนช่องที่กำลังเปิดอยู่เข้ามาในจอเอง
(`scrollIntoView({ block: "nearest", inline: "nearest" })`)

**บทเรียน: "วัดสองภาษา" ไม่ใช่การเผื่อภาษาที่ยาวกว่า — เป็นการวัดสองครั้งจริง ๆ**
เพราะแถบที่พอดีกับภาษาหนึ่งพังกับอีกภาษาได้ทั้งสองทิศทาง

### 3.4 `dev:session` สร้างรอบ `OPEN` ใบที่สอง

เครื่องมือ dev ตัวนี้เปิดรอบใหม่แทนที่จะเข้าร่วมรอบที่เปิดค้างอยู่ ผลคือโต๊ะเดียว
มีสองรอบ `OPEN` แล้วทุกที่ที่ใช้ `findFirst(orderBy openedAt desc)` เห็นแต่ใบใหม่
ส่วนใบเก่า **มองไม่เห็นแต่ยังบล็อกการคิดเงิน** — ตระกูลเดียวกับบั๊ก `expiresAt`
ที่แก้ไปเมื่อ 2026-08-25 แก้แล้วที่ `f02ceb4`

### 3.5 เลขภาษี: กฎคนละอย่างต่อประเทศ

ตัวตรวจเดิมบังคับ 13 หลักแบบไทยตายตัว สาขาเวียดนามกรอกเลขจริง (10 หลัก หรือ
13 หลักแบบมีขีดสำหรับสาขา) ไม่ผ่าน

→ `lib/server/settings.ts` คืนคีย์ `error.tax_id_invalid.${currency}` และมีสามคีย์
ในพจนานุกรม (THB/VND/LAK) — **กฎผูกกับสกุลเงินของสาขา ไม่ใช่ฮาร์ดโค้ดไทย**
ตระกูลเดียวกับหมายเหตุ PromptPay ที่เขียนไว้ใน CLAUDE.md

### 3.6 `intlLocale()` ใช้ได้เฉพาะวันที่ที่ render บน server

`Intl.DateTimeFormat` ใช้กับรูปแบบที่มี **ชื่อเดือน** เท่านั้น ("11 thg 9, 2026" /
"11 Sept 2026") และ **ห้ามใช้ใน client component** เพราะ ICU ของ server กับ browser
ต่างกันได้ → hydration mismatch (เหตุผลเดียวกับที่ `formatAmount()` ไม่ใช้ `Intl`)
รูปแบบตัวเลขล้วน (dd/mm/yyyy) ใช้ `"en-GB"` ต่อได้เพราะเวียดนามเรียงแบบเดียวกัน

### 3.7 subset ฟอนต์ที่ถ้าถอดออกแล้วสัญลักษณ์เงินพัง

`app/layout.tsx` ขอ Archivo แบบ `subsets: ["latin", "vietnamese"]` และ **ตัด
Noto Sans Thai ออก** ตรวจจาก `@font-face` ที่ emit ออกมาจริง ไม่ใช่เชื่อ option:

```
U+102-103, U+110-111, U+128-129, U+168-169, U+1A0-1A1, U+1AF-1B0,
U+300-301, U+303-304, U+308-309, U+323, U+329, U+1EA0-1EF9, U+20AB
```

ครอบ Ă ă · Đ đ · Ơ ơ · Ư ư · สระประสมทั้งชุด — และ **U+20AB คือสัญลักษณ์ ₫ เอง**
ถอด subset นี้ออกเมื่อไหร่ สัญลักษณ์เงินบนทุกหน้าจอตกไปใช้ฟอนต์ระบบทันที

### 3.8 เทสต์ที่เทียบยอดเงินแบบเขียนตัวเลขไว้เอง พังทั้งชุดตอนเปลี่ยนสกุลเงิน

Task 10 เปลี่ยนทุกจุดให้ **คำนวณยอดที่คาดหวังจากราคาใน DB + `calculateBill()`**
ด้วยอัตราสดของสาขา ไม่ใช่เขียนเลขไว้ในเทสต์:

- `bill`: รวม subtotal จากราคาใน DB
- `takeaway`: ยอดเคาน์เตอร์ = `calculateBill({serviceChargeBp: 0, vat, pricesIncludeVat})`
  — ของเดิมเขียนว่า "grandTotal = subtotal" ซึ่งจริงเฉพาะกรณี THB ที่ราคารวม VAT แล้ว
- `menu`: `parseMoneyInput(text, branch.currency)` แทนการเขียนสตางค์บาทลงไปตรง ๆ
- `receipt`: เคสจ่ายเงินสดแบบปัดขึ้นต้องจ่ายยอดจริงของบิล (100.000 ₫ จ่ายไม่พอ)

### 3.9 กับดักเล็กที่กินเวลาจริง

- **`loginStaff()` มี union variant ที่ไม่มี `params`** — ต้อง narrow ด้วย
  `"params" in result` ไม่งั้น tsc พัง (รัน `tsx` เฉย ๆ จับไม่ได้)
- **regex `\.error` กวาดโดน `console.error` ไป 20 ไฟล์** — จับได้เพราะไล่อ่าน diff
  ไม่ใช่เพราะ tsc (มัน type-check ผ่าน) · **แทนที่แบบกวาดทั้งโปรเจกต์ต้องตามด้วย
  การอ่านสิ่งที่มันเปลี่ยนจริงเสมอ**
- **heredoc ของ Git Bash บน Windows กินแบ็กสแลชในสคริปต์ Node** — และไฟล์ที่มี
  อักษรเวียดนาม/ไทยควรเขียนด้วยเครื่องมือเขียนไฟล์ กัน encoding เพี้ยนเงียบ ๆ
- **Git Bash แปลงอาร์กิวเมนต์ที่ขึ้นต้นด้วย `/`** — `node print-check.mjs /pos/receipt/...`
  ได้ `Cannot navigate to invalid URL` ต้อง `export MSYS_NO_PATHCONV=1` ก่อนเสมอ

### 3.10 `mustSee` ของตัววัดจอที่ชี้ไปยังของที่ตั้งใจซ่อน (เจอในก้อนนี้)

`/pos/table/[id]` และ `/pos/counter/[id]` FAIL 12 เคสที่ 390/768/1024 เพราะ `mustSee`
ชี้ไปที่ "Tổng giỏ hàng" / "Gửi 2 món vào bếp" ซึ่งอยู่ใน**เนื้อในของตะกร้า** — ต่ำกว่า
`xl` ตะกร้าเป็นแถบสรุปที่พับอยู่ตามดีไซน์ ของพวกนั้นจึงเป็น 0×0 โดยถูกต้อง

→ เปลี่ยน `mustSee` ไปที่ของที่อยู่ใน**แถบสรุปที่พับแล้ว**: ชื่อตะกร้า · จำนวนรายการ
(`2 món` / `2 items`) · **ยอดรวม** (`30.000 ₫`) — ยอดรวมสำคัญที่สุดเพราะเป็นบั๊ก
ตระกูล "รวมทั้งสิ้นหายจากจอ" ที่ผู้ใช้เคยจับได้ **ไม่ใช่บั๊กจอ เป็น config ของตัววัด**

วัดด้วย `npm run audit:screens` ต่อ prod build เท่านั้น (ไม่ใช่ dev server)
ตัววัดถามห้าข้อ: ล้นแนวนอน · ล้นแนวตั้ง · ของที่ต้องเห็นถูกกล่องแม่ตัดทิ้งไหม ·
โซน `overflow-auto` ถูกบีบจนแบนไหม · **ของในแถบหัวจอยื่นออกนอกกล่องไหม**

### 4.3 ตรวจการพิมพ์ — 4 ชุด ผ่านหมด

### 4.4 กวาดหาภาษาไทยที่ตกค้าง — **0 จุด**

ยิง HTML จริงจากเซิร์ฟเวอร์ **28 หน้า × 2 ภาษา** แล้ว grep `[ก-๙]` ไม่เจอเลยสักตัว

> ระหว่างทางเจอผลบวกลวงหนึ่งครั้ง: `1 items` ในหน้าภาษาเวียดนาม ซึ่งกลายเป็นคลาส
> Tailwind `flex-1 items-center` ไม่ใช่ข้อความ — **กวาดด้วย regex บน HTML ดิบต้อง
> อ่านบริบทของทุก hit ก่อนสรุป**

## 5. ที่ตั้งใจไม่ทำ

- **ไม่ใส่ locale ลง URL** — QR ที่พิมพ์ไปแล้วเข้ารหัส `/t/<tableCode>` ไว้ ภาษาอยู่ใน cookie
- **ไม่เดาภาษาจาก `Accept-Language`** และไม่มี region variant (vi-VN/en-US) — คนที่ยืน
  อยู่หน้าเครื่องเป็นคนเลือก แท็บเล็ตในครัวกับโน้ตบุ๊กเจ้าของร้านตั้งคนละภาษาได้
- **คอมเมนต์ในโค้ดยังเป็นภาษาไทย** ตามคอนเวนชันเดิม — แปลเฉพาะข้อความที่ผู้ใช้เห็น
- **คำเตือน "ระบบสาธิต" บนใบเสร็จยังฮาร์ดโค้ด** แก้ไม่ได้จากหน้าตั้งค่า (ของเดิม)
- **ไม่แตะ payment จริง** — PromptPay เป็นของไทย สาขา VND ต้องใช้ VietQR (NAPAS)
  ซึ่งเป็น EMVCo เหมือนกันแต่คนละ tag/ผู้ให้บริการ
- **ไม่มีฟีเจอร์ใหม่** — บทที่ 15 (รายงาน/ปิดกะ) คือก้อนถัดไป
